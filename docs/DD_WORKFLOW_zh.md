启动原来的工作台，首页现在是七步箭头流程：

**显微扫描 → 日志交接 → 自动校色 → 大面积拼接 → 图像复核 → 层数识别 → Figure4空间图**

点击箭头中的步骤会切换页面；切换页面不会把实验标为完成。右边显示本批次状态、实际任务、运行日志和 `Memory` 入口。原有四项复核工具保留在 `/review/`。

## 学生按哪里

1. **显微扫描：打开扫描程序。** 老师先在“项目与仪器设置”连接已经核对过的通信日志版扫描文件夹。新入口核对交付清单和日志模块，避免误开旧版本；不会替换采集文件。相机连接、调焦、3×3验证及大面积扫描仍在原有Windows采集窗口完成。
2. **日志交接：检查本批次记录。** 填写包含原图、`session.json`和`events.jsonl`的完整文件夹。程序核对原图尺寸、行列、数量、记录与哈希。未完成或缺记录时停下；多轮交接有歧义时交老师核查，不混合不同样品。它登记和留存日志，不创建新的压缩包。
3. **自动校色：检查原图并准备拼接。** 进入原有图像检查页。首次采集几何由老师核对并保存；不从步数或分辨率猜测物理标定。校色默认开启，学生不用选算法。
4. **拼接：开始自动校色与拼接。** 配置保存后可直接按此按钮，不必复制终端命令。程序在后台运行，页面显示实际阶段和日志。每张照片RGB增益在渲染时应用；原图不变。旧校色数据逐图核验后避免重复增益，证据不足时停止。
5. **图像复核：打开结果和校色记录。** 核对覆盖、接缝、颜色、实际参与图像与失败项。退出码0不等于通过；后台还检查输入绑定、渲染清单、颜色状态及输出文件。被改动的结果不会继续按已核验文件提供。
6. **层数识别：运行老师确认的配置。** 仅接受明确确认样品/模型和尺度的配置，核对原0409清单与权重SHA；不会自行切换样品体系或模型。现有Python分割/区域/统计流程生成新结果，原数据不覆盖。结果仍需人工核查，不能把预测当独立测量。
7. **Figure4空间图：生成空间分布图。** 单样品层数任务完成后自动带入原生mask、有效区及排除区；也可以明确选择已保存的分割数据。复用现有算法输出8×15热图、6×11组合分布、整体/行列统计、PNG/SVG/CSV和来源清单。局部比例在该格保留的MoS₂面积内归一化。没有有效区域文件时必须明确确认整幅画布均有效；坐标没有物理标定时不会伪造毫米尺寸。生成的是可复核分析图，正式稿件排版仍单独保留。

## 统一 Memory

项目根目录配置为DD项目时，历史集中到：

```text
<DD项目>/Memory/
  events.jsonl                  主流程追加记录
  index.json                    索引及旧历史来源
  acquisition/                独立扫描日志快照、原文件SHA
  device_runs/                 共用设备运行日志，按身份和内容去重复
  dd_workflow/
    events.jsonl               每个后台步骤的准备、开始、结束及异常
    prepared/                  后台生成并绑定的任务参数
    jobs/<id>/                 任务状态与过程日志
    stitch_runs/               拼接配置、校色记录、配准及渲染结果
    analysis_outputs/          分割和空间分析的新结果
```

实际文件夹与清单路径以Memory索引为准。若项目选为原始扫描文件夹，Memory置于其父目录，避免混入原图清单。旧的`workbench_history/`和原始采集日志保留，通过来源索引关联，不重写历史。

同一进程的3×3和1000张扫描保持两个独立扫描记录，共用通信日志不重复当成两次运行。日志快照有大小限制、来源前后状态和截断说明；Windows路径在另一台Mac上不可读时明确标为缺失，不猜路径或假装全部保存。照片、DLL和`.env`不复制进日志快照。`Memory/`不进入Git或后续学生包。
