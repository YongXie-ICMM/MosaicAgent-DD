## Candidate code versus the distributed student baseline

- [69ceb6c](https://github.com/YongXie-ICMM/AmScope-Camera/commit/69ceb6ceed5b27f7fd56656b0f00b027f96bb167) implemented, in the v3.4.1 candidate, at most four query attempts, interruptible 0.1/0.2/0.3 s backoff, live motor-configuration queries and JSON Boolean blur flags.
- Later on 1 October, [f409384](https://github.com/YongXie-ICMM/AmScope-Camera/commit/f409384fcf7d99b938dabe2b513f4d848248eb3c) deliberately selected the student core associated with the 954-point run and added the language layer. That core retained connection-time motor-configuration caching and `time.sleep` backoff. An ancestor commit therefore does not prove that every candidate feature remained in a subsequent delivery.
- [25a8392](https://github.com/YongXie-ICMM/AmScope-Camera/commit/25a839261ae033f068bdcc84507a8cb0e749f760), committed 5 October, primarily added received-frame checks for 1920×1080 and cross-tool records. It retained the selected motion/retry baseline; it was not a demonstrated fix for motion return -1.
- The later retake categories separate normal post-focus retakes, abnormal retakes, automatic retries and terminal outcomes. They improve counting and observability; old unclassified events cannot be retrospectively assigned individual motives.
- C1 records SDK calls, return values, controller states, XILOG, camera operations and fault-window stacks. Native calls share a command lock; diagnostic disk I/O stays outside it; cancellation is checked immediately before movement dispatch; stopping precedes diagnostic collection. Offline regressions cover these safety boundaries. They do not identify the 11 October root cause.

Current limits include cached motor configuration during a connection, potentially blocking native SDK calls and unverified physical position after restart. The old suggestion to resend a relative command once is historical proposed work, not the deployed C1 policy. Controller counters alone are not an independent mechanical-position measurement.

## Publication and reproducibility scope

The records link specific observations to source changes without replacing raw data, historical manifests, model weights or experimental settings. The DD workflow publication is tracked in [pull request #3](https://github.com/YongXie-ICMM/MosaicAgent-DD/pull/3); this page does not claim it has merged into `main`. Acquisition C1 is maintained in the separate [AmScope-Camera repository](https://github.com/YongXie-ICMM/AmScope-Camera).

Normal-path instrument trials, synthetic regressions, recorded-data module replay, source publication and release packaging are distinct evidence. Full Windows workflow acceptance and real fault-triggered evidence remain separate from the completed checks above.
