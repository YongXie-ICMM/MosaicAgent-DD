**[下载完整学生试跑包](https://github.com/YongXie-ICMM/MosaicAgent-DD/releases/latest)**：选 `MosaicAgent-DD-student-complete.zip`，包含程序、两张当前1920 × 1080原图、真实权重和启动文件。GitHub自动生成的Source code ZIP不包含原图压缩包和权重。每个学生包都在 `bundle_manifest.json` 里记录打包时的提交号；GitHub 上的 release 可能比 `main` 旧（见下面"当前状态与待办"）。

**一步一步的学生说明书（PDF）：学生包最外层的 `00_STUDENT_GUIDE_zh.pdf`**，源文件是 [docs/STUDENT_GUIDE_zh.md](docs/STUDENT_GUIDE_zh.md)（分析电脑四个启动文件 01–04；仪器电脑扫描日从 `acquisition/Auto_Scan/00_white_balance_then_scan.bat` 进入：先在干净裸衬底上把白平衡校正到参考值并记录，再调用原来的扫描程序）。

## 拿到完整试跑包之后

1. 把整个压缩包解压到一个可写文件夹。不要只取出其中一个 Python 文件。
2. 双击 **01_install**：首次安装环境。需要 Python 3.10 以上和联网下载依赖；窗口结束前不要关闭。
3. 双击 **02_run_layer_demo**：程序先核对原图和权重，再预测两个1920 × 1080示例；出现结果路径后再关闭窗口。
4. 双击 **03_open_workbench**：进入统一工作台，打开 **03 / 层数分析**，对照原图与预测图检查。默认不显示 overlay。
5. 拿到扫描交接文件夹后，双击 **04_process_handover**，把文件夹拖进窗口，跑完看文件夹里的 `analysis\REPORT_zh.md`（见下面"学生交一个文件夹就够了"）。

Windows 使用 `.bat`；macOS 使用 `.command`。每次预测放在新的 `outputs/demo/` 子文件夹，原图、权重和上次结果不覆盖。完整包使用相对位置；电脑用户名改变不需要手动重写路径。实际显微镜采集仍在 Windows 仪器电脑上运行。

**完整包必须包含：** `data/demo/source_images.zip`、`data/demo/assets.json`、`weights/model_0409_all.pth`。发给本组学生的是**内部版** `MosaicAgent-DD-student-complete-with-kimi.zip`，多一个老师配好的 `.env`（Kimi 密钥）：拼接时 Kimi 像原流程一样做质检投票、同格位二选一和接缝抽查；工作台"检查新扫描图片与拼接设置"检测到密钥就不再加 `--no-ai`。内部版只在组内流传，不要上传到 GitHub release；公开版 `MosaicAgent-DD-student-complete.zip` 不含密钥，拼接自动退回纯统计判据。如果看到“缺少资源”，说明拿到的是仅含代码的 GitHub 包；请使用老师提供的完整学生包，不要随意下载名字相近的权重。下载代码不等于已经拿到实验数据。

**这两张当前示例的衬底为260 nm SiO₂/Si（老师2026-10-05确认；旧称276 nm），不是70 nm。采集为1920 × 1080。**

**当前试跑结论：0409权重没有改动。直接预测和尺度对照均已跑通，但尺度调整没有消除“大片看起来像衬底的区域被分为单层”的目视疑问。2026-10-05 的对照实验找到了原因：不是分辨率变化（把历史 4K 图合成降到 1920×1080，同一权重仍能正确识别衬底，召回率 ≥ 99%），而是**新采集模式的颜色/白平衡**偏蓝、偏绿不足，整张图被读“厚一级”。只做每通道增益校正就能恢复正常结构，反过来把历史图染成新色调也能复现错误。详见[对照记录](docs/diagnostics/20261005_colour_balance/README.md)。目前仍没有这两张图的独立参考标签，也没有准确率验证，因此校正后的结果也只是诊断预览，不能把这些比例用于论文统计。先在采集端把白平衡调回去，不需要学生修改算法。**

**02_run_layer_demo 现在每次都会做一项颜色检查**：把原图里干净裸衬底的颜色与参考衬底颜色 (219,171,170) 比较，算出每通道增益；偏差超过 5% 时窗口会用中文提示“颜色/白平衡与参考衬底颜色不一致”，结果自动标为需复核。学生重拍前在仪器电脑上运行 `acquisition/Auto_Scan/00_white_balance_then_scan.bat`：对准一块干净裸衬底，程序关掉自动白平衡和自动曝光，自动把曝光、色温/色调调到裸衬底读数约 (219,171,170)（相机不可控时显示实时读数，由学生在相机菜单里调），把当时的衬底图、曝光、色温、色调、读数写进 `acquisition/Auto_Scan/colour_calibration/`，再启动原来的扫描程序；灯光亮度和物镜由程序询问后记录。之后同一视野、同一样品分别拍 1920×1080 和（相机若支持）3840×2160 各一张，其它设置都不动。这些记录和测试图随本次采集一起交回。

老师现已确认：只把相机分辨率由3840 × 2160改为1920 × 1080，物镜、放大倍率和实际视野均未改变。当前两张图的完整包会记录这项确认；学生仍按三个启动文件操作，**02_run_layer_demo会自动按原图256 × 256、重叠32像素切块，再送入512 × 512模型窗口**，无需手工改参数。只有未设置 `capture_geometry` 字段的旧资源仍使用原生512 × 512、重叠64像素的基线；如果已设置该字段但没有确认实际视野相同，或记录无效，程序会报错并停止，要求核对记录。

这项操作人员确认支持像素尺度换算，不是独立的微米标定，也不代表准确率已经提高。重采样不会恢复拍照时损失的细节。具体命令和限制见[分辨率与预测说明](docs/RESOLUTION_AND_INFERENCE.md)。

## 学生这次要交什么

- 核对两个示例中原图与预测图是否一一对应，截图指出明显错分的位置。
- 记录安装是否成功、预测是否结束、报错原文和所用电脑系统。

## 扫描中断、重拍后列间有色差，或拼接图上能看出一格一格的边界怎么办

`python tools/colour_match_grid.py --data <扫描文件夹> --stitch`：先从这批图自己估计照明场（每张图除以自身均值后逐像素取中位数，样品内容互不相关就被抵消，剩下的是照明的左暗右亮、上暗下亮），再把每一对相邻图配准、在重叠区比较颜色，然后一次性解出"每列一个水平 + 每张图一个受约束的小偏差"，让全部约 1600 个重叠都对得上：重拍的两列整体校正，相机自动曝光对某一张的反应单独校正，而某一类重叠里 0.1 % 的系统误差不会沿 50 行累加成坡。原图一律不动：派生数据集里被校正的是新副本（不需要改的用硬链接），同时生成带新校验值、照明场和每张增益记录的 `session.json`/`events.jsonl` 和实测拼接参数，然后直接调用 `run_stitch.py`（配置了 Kimi 就用 Kimi）。只想看结论加 `--report-only`；`--gain-mode column` 退回每列一个增益；`--no-flat-field` 不做照明校正。2026-10-06 的 16×53 扫描：最后两列来自第二次相机会话（增益 27 对 21），列增益约 (0.95, 0.94, 0.91)；第一轮内部两处约 3 % 的小台阶、单张最多 4 % 的曝光差、以及左右 7 %／上下 3 % 的照明差一并校正，拼接后看不出格子。2026-10-03 的 18×50 扫描 261002AM（一轮）：没有列台阶，单张偏差最多 4 %，照明左右差 3–4 %、上下 ≤ 1 %。

## 学生交一个文件夹就够了（2026-10-07 起）

仪器电脑扫完当天双击 `acquisition\Auto_Scan\04_pack_handover.bat`：把当天每一轮扫描原样复制（原图、`session.json`、`events.jsonl`、程序快照，几轮绝不手工合并）、控制台记录、采集日志、相机连接记录、白平衡记录和扫描程序清单放进一个交接文件夹，`handover.json` 记每个文件的 SHA-256、每一轮的网格、张数、相机增益和中断事件。分析电脑双击 `04_process_handover`，把文件夹拖进去：核验 → 按原行列号把几轮拼成一张网格（记每张来自哪一轮、重复与缺失、跨轮接缝配准）→ 中断时间线 → 颜色/照明校正 → 拼接 → 颜色检查 → `analysis\REPORT_zh.md`。每一步从上一步在 `analysis\` 里的结果接着做，`handover_status.json` 记录进度，再跑一次会跳过已完成的步骤（`--from <步骤>` 从某一步重做）。报告还会把解出的瓦片位置与刚性网格模型比对（偏离超过四分之一瓦片的列出来），并把参考颜色检查拆成"整体亮度"和"色彩平衡"两项，能分清"只是暗"和"偏色"。交接文件夹和扫描记录在同一块盘上时，`pack_handover.py --link` 用硬链接代替复制。

## 拼接时瓦片被挪错行（2026-10-07 起已防住）

`register.py` 先用上下重叠把每一列连成链；链断开的地方，再用左右相关决定那一段要不要挪行。现在只有证据够硬才挪（`decide_segment_offset`）：单条左右边的 NCC 要 ≥ 0.5，而且非零偏移的平均 NCC 要比"不挪"高 0.1（或者够格的边更多），否则保持扫描记录的行号。这修好了 261002AM 芯片边缘两张瓦片（一半衬底、一半芯片外的暗区）被一条 NCC 0.27 的边挪高 2–3 行、在拼接图上留下重影和空洞的问题；Figure 3a 那种多张、强证据（NCC 0.78–0.92）的段不受影响。交接报告里的"位置核对"会把这类异常直接列出来。

## 换成新扫描数据

先使用 **02 / 图像与拼接 → 检查新扫描图片与拼接设置**。选择本次原始采集文件夹，同时保留 `session.json` 和 `events.jsonl`。核对实际图片像素、相邻视野重叠及采集设置后，使用生成的拼接命令。不要用文件大小4 MB/2 MB推断位移应缩小一半。

设置工具会一起保存 `layer_input_contract.json`、`profile.json` 和 `preflight.json`，把真实像素、文件绑定和采集核对状态传给后续层数分析。这里保存的是元数据，不代表已经完成拼接或已经确认权重适用。不要仅凭分辨率就勾选“实际视野相同”；缩小后的拼接图（`out_scale != 1`）暂不允许自动套用该尺度换算，需要明确建立坐标映射。

新相机模式、物镜或步长要先完成小范围上机验证。采集安装及恢复方法见[采集说明](acquisition/README.md)。现有本机实验目录继续使用原路径；可通过工作台“连接工具”选择，不会搬走数据。
